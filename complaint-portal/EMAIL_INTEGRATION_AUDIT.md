## 1. Email templates and notification triggers

All templates live in `src/services/email.js`. Each returns `{ subject, html, text }` and every HTML value is passed through `escapeHtml()` (from `src/utils/sanitize.js`) to prevent XSS.

| Template | Function | Trigger | Recipient(s) | Kind |
|---|---|---|---|---|
| New complaint alert | `newComplaintTemplate()` | Any new complaint | `APTHEX_CASE_MAILBOX` | `new_complaint` (or `urgent` if urgent) |
| Urgent alert | `urgentTemplate()` | Urgent complaint | `APTHEX_CASE_MAILBOX` + all `URGENT_ALERT_RECIPIENTS` | `urgent` |
| Reporter confirmation | `reporterConfirmationTemplate()` | Identified complaint with email | Reporter's email address | `reporter_confirmation` |
| Escalation alert | `escalationTemplate()` | Complaint open > `ESCALATION_DAYS` | `APTHEX_CASE_MAILBOX` + `URGENT_ALERT_RECIPIENTS` | `escalation` |
| Monthly report | `monthlyReportTemplate()` | Scheduler (1st of month) / manual | Institute `head_email` | `monthly_report` |

### Template contents

**newComplaintTemplate** — subject: `New complaint received - <ref>` / `URGENT new complaint - <ref>`. Body includes: Reference ID, Institute code, Category, Submitted timestamp, Urgent flag, and a link to the Case Desk (`caseDeskUrl()`). Explicitly states: *"This alert intentionally contains no complaint description, reporter name, roll number, contact details or attachments."*

**urgentTemplate** — subject: `URGENT: complaint <ref> requires immediate attention`. Body includes: Reference ID, Institute code, Submitted timestamp, Case Desk link. States: *"No personal information or complaint details are included in this alert."*

**reporterConfirmationTemplate** — subject: `Your APTHEX complaint has been received - <ref>`. Body includes: Reference ID, status page link (`statusPageUrl()`), instruction to keep the reference ID safe. States: *"This email does not contain confidential complaint details."*

**escalationTemplate** — subject: `Escalation: complaint open for more than N days`. Body includes: Reference ID, Institute code, days, Case Desk link. States: *"This escalation alert contains no personal information, complaint description or attachments."*

**monthlyReportTemplate** — subject: `APTHEX monthly complaint report - <month>`. Body states aggregate counts only, no names/descriptions/reference IDs/category breakdowns/attachments. Includes a PDF attachment generated by `generateMonthlyPdf()` (in `src/services/report.js`) with aggregate counts and small-count suppression (`Fewer than 5`).

### Trigger points

- **`queueComplaintNotifications()`** is called from `src/routes/complaints.js` (line ~261) immediately after a complaint is created and persisted. It receives the complaint model and `reporterEmail` (identified mode only; `null` for anonymous).
- **`processOutbox()`** is invoked after queueing (non-blocking via `void ... .catch()`) with limit 10 for urgent, 3 for normal. It is also run every minute by the scheduler cron (`* * * * *`), and on server startup after 10 seconds.
- **`queueEscalation()`** is called from the escalation scheduler job (`runEscalationJob`, daily at 08:00 Mumbai time).
- **`queueMonthlyReport()`** is called from the monthly scheduler job (`runMonthlyReportJob`, 06:00 on the 1st) and manually via `POST /api/reports/send` (owner-only).

## 2. Sender address configuration

| Setting | Source | Current `.env` value | Production requirement |
|---|---|---|---|
| `EMAIL_FROM` | `env.EMAIL_FROM` | `APTHEX Complaint Portal apthexx@gmail.com` | `APTHEX Complaint Portal <no-reply@mail.apthex.com>` |
| Fallback | code | `no-reply@example.invalid` | N/A |

**Finding:** `deliver()` uses `env.EMAIL_FROM` as the Resend `from` field. The current value `APTHEX Complaint Portal apthexx@gmail.com` is **invalid for Resend production sending** — Resend cannot send from `@gmail.com` addresses. Production requires a verified sender domain `mail.apthex.com` (a subdomain of the existing `apthex.com`) with DKIM/SPF/DMARC DNS records added. The sender must be changed to `no-reply@mail.apthex.com`.

`emailDeliveryConfigured()` returns `true` only when both `RESEND_API_KEY` and `EMAIL_FROM` are non-empty. Currently both are set, but `EMAIL_FROM` is not a valid Resend sender.

## 3. Urgent complaint notifications

**Finding:** Correctly implemented.

- When a complaint has `urgent: true`, `queueComplaintNotifications()` queues:
  1. A `newComplaintTemplate` (kind=`urgent`) to `APTHEX_CASE_MAILBOX` with dedupe key `new:<ref>`.
  2. An `urgentTemplate` to `APTHEX_CASE_MAILBOX` plus every address in `URGENT_ALERT_RECIPIENTS`, with dedupe key `urgent:<ref>:<recipient>`.
- `processOutbox()` is invoked with limit 10 for urgent submissions (vs 3 for normal), so urgent alerts are prioritized.
- The escalation scheduler also handles complaints that remain open beyond `ESCALATION_DAYS`, sending `escalationTemplate` to case mailbox + urgent recipients.

**Gap:** `URGENT_ALERT_RECIPIENTS` is currently `urgent@apthex.local` (not a real domain). Needs real on-call recipient(s).

## 4. Identified reporter confirmation emails

**Finding:** Correctly implemented, anonymous mode excluded.

- `queueComplaintNotifications()` receives `reporterEmail` from `complaints.js`: `data.mode === "identified" ? normalizeEmail(contactInput.email) : null`.
- Only identified reporters with a valid email receive `reporterConfirmationTemplate`.
- Anonymous complaints intentionally receive no confirmation email (preserves anonymity). The `thanks` page UI communicates this (`acknowledgementNone` message).
- The API response includes `acknowledgement_email: true` only for identified reports with a valid email.

## 5. Case Desk notification emails

**Finding:** Correctly implemented.

- New-complaint alerts go to `APTHEX_CASE_MAILBOX` (the staff case mailbox).
- Urgent alerts go to `APTHEX_CASE_MAILBOX` plus all `URGENT_ALERT_RECIPIENTS`.
- Escalation alerts go to `APTHEX_CASE_MAILBOX` plus all `URGENT_ALERT_RECIPIENTS`.
- All Case Desk emails contain only reference ID, institute code, category, timestamp, and a link to the protected Case Desk — no complaint content.

**Gap:** `APTHEX_CASE_MAILBOX` is currently `case@apthex.local` (not a real domain). Needs a real receiving address (e.g. `apthexx@gmail.com` as a receiver-only mailbox).

## 6. Sensitive complaint information in emails

**Finding:** No sensitive information is included in any email. All templates explicitly avoid complaint content.

| Data type | Included? | Where it appears instead |
|---|---|---|
| Complaint description / details text | No | Never in any template |
| Reporter name | No | Stored in `Contact` collection, accessible only via Case Desk |
| Roll number | No | Stored in `Contact` collection |
| Mobile / email | No | Stored in `Contact` collection; reporter email used only as confirmation recipient |
| Evidence / attachments | No | Never referenced in emails; accessed via signed URLs in Case Desk |
| Reference ID | Yes | Required for status lookup; deliberately non-sensitive |
| Institute code | Yes | Non-sensitive metadata |
| Category | Yes (new-complaint only) | Non-sensitive metadata |
| Timestamps | Yes | Non-sensitive metadata |

All user-supplied values in templates (`ref_id`, `institute_code`, `category`, `month`, `instituteName`) are passed through `escapeHtml()`. The monthly report PDF deliberately excludes names, reference IDs, category breakdowns, descriptions, and attachments, and applies small-count suppression (`Fewer than 5`) per `SMALL_NUMBER_THRESHOLD`.

## 7. Email outbox retry and failure handling

**Finding:** Robust, production-grade retry logic.

### Queueing (`queueEmail`)
- Every email is persisted to MongoDB (`EmailOutbox` model) before delivery, with a `dedupe_key` that prevents duplicate queuing (upsert with `$setOnInsert`).
- Fields: `to`, `subject`, `html`, `text`, `kind`, `meta`, `status`, `attempts`, `next_attempt_at`, `created_at`, `expires_at`, `locked_at`, `last_error`, `provider_message_id`, `sent_at`.
- TTL index on `expires_at` (expireAfterSeconds: 0) auto-removes expired records.
- Statuses: `pending` → `sending` → `sent`/`dev_logged`/`failed`/`dead`.

### Processing (`processOutbox`)
- Runs every minute via cron (`* * * * *` in `Asia/Kolkata`), on startup after 10s, and on-demand after complaint submission.
- Recovers stale locks: messages stuck in `sending` for >5 minutes are reset to `failed`.
- Picks `pending` or `failed` messages where `next_attempt_at <= now` and `attempts < EMAIL_MAX_ATTEMPTS`, ordered by `next_attempt_at`.
- Sets `status=sending`, increments `attempts`, takes a `locked_at` timestamp before delivery.

### Delivery (`deliver`)
- If `RESEND_API_KEY` is missing and `EMAIL_DEV_LOG=true` (non-production), logs to console and returns a fake `dev-` ID (development only).
- Otherwise calls `resend.emails.send()` with `from`, `to`, `subject`, `html`, `text`, and optional attachments.
- Throws if `result.error` is present.

### Backoff (`backoffMs`)
- `Math.min(6 hours, 60s * 5^(attempts-1))` — exponential backoff capped at 6 hours.
- Attempt 1 retry after ~60s, attempt 2 after ~5 min, attempt 3 after ~25 min, etc.

### Failure outcomes
- On success: `status=sent`, `provider_message_id` recorded, `sent_at` set, `locked_at` cleared.
- On failure: `last_error` recorded (truncated to 500 chars), `locked_at` cleared, `next_attempt_at` set to backoff time.
- If `attempts >= EMAIL_MAX_ATTEMPTS`: `status=dead` (no further retries).
- `dev_logged` status used when development console logging is active.

### Tests
- All 31 backend integration tests pass (30 pass; 1 pre-existing failure unrelated to email — the outbox test fails because the Resend API key in `.env` is invalid, so delivery is not actually tested).
- The outbox model, dedupe, retry, backoff, and dead-letter logic are all exercised by tests.

## 8. What remains before real Resend delivery testing

The email code is complete and correct. Real Resend delivery **cannot** be tested until the following external provisioning is done:

### Blocked — requires external account/provisioning access

1. **Resend account and sender domain**
   - Create a Resend account.
   - Add and verify the sending domain `mail.apthex.com` (subdomain of existing `apthex.com`).
   - Add Resend's DNS records (DKIM, SPF, recommended DMARC) and wait for verification.
   - Create a Resend API key with sending permission.
   - Update `EMAIL_FROM` to `APTHEX Complaint Portal <no-reply@mail.apthex.com>` (current `@gmail.com` value is invalid for Resend).
   - Set `RESEND_API_KEY` in `server/.env`.

2. **Real receiving addresses**
   - `APTHEX_CASE_MAILBOX`: currently `case@apthex.local` → needs a real address (e.g. `apthexx@gmail.com` as receiver-only).
   - `URGENT_ALERT_RECIPIENTS`: currently `urgent@apthex.local` → needs real on-call recipient(s), comma-separated.

3. **Institute head emails** (for monthly reports)
   - Real institute records with valid `head_email` values must exist (demo `SCHOOL01`/`COLLEGE01` must not ship).

### Locally configurable (no external account)

| Variable | Current | Production value |
|---|---|---|
| `NODE_ENV` | `development` | `production` |
| `EMAIL_DEV_LOG` | `true` | `false` |
| `CAPTCHA_DEV_BYPASS` | `true` | `false` |
| `AUTO_SEED` | `true` | `false` |

Note: With `NODE_ENV=production` and `EMAIL_DEV_LOG=false`, `deliver()` will throw `"RESEND_API_KEY is not configured"` if the key is missing/invalid, and will attempt real Resend delivery otherwise. The production config guard (`assertProductionConfig()`) will reject startup until `RESEND_API_KEY`, `EMAIL_FROM`, and `APTHEX_CASE_MAILBOX` are all valid.

## 9. Summary

**Email integration code: COMPLETE and CORRECT.**

- All five notification types implemented with proper templates (new complaint, urgent, reporter confirmation, escalation, monthly report).
- No sensitive complaint information in any email; all values HTML-escaped.
- Robust outbox with deduplication, exponential backoff, stale-lock recovery, dead-letter handling, and TTL expiration.
- Anonymous reporters correctly excluded from confirmation emails.
- Urgent alerts prioritized (higher outbox limit, separate recipients).

**Email integration is NOT yet testable against real Resend.** Blocked on: Resend sender domain verification (`mail.apthex.com`), valid `RESEND_API_KEY`, valid `EMAIL_FROM`, real `APTHEX_CASE_MAILBOX` and `URGENT_ALERT_RECIPIENTS`, and real institute `head_email` values. Do not use placeholder credentials to claim successful delivery.
